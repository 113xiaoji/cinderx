## 一、概述

将递归树遍历生成器（`Node.__iter__`）的 `yield from` 调用内联为显式状态机，消除帧切换开销。

### 核心思路

```
当前: yield from self.left → 分配生成器帧 → yield → 恢复帧 → 循环
优化: 状态机循环 → LoadField → CondBranch → YieldValue → 无帧切换
```

### 设计目标

| 指标 | Week 1 | Week 2 |
|------|--------|--------|
| depth=3-5 正确遍历 | ✅ | ✅ |
| depth=3-5 性能 | 2-3x | 4-6x |
| depth=10-12 正确遍历 | — | ✅ |
| depth=10-12 性能 | — | 4-6x |
| depth>12 回退 | — | ✅ |

## 三、剩余工作详细分析

### 核心问题：11 个占位符

状态机生成器 (`tree_iter_state_machine_pass.cpp`) 中有 **11 处占位符**，全部是 Task 5 的工作范围。这些占位符导致状态机无法产生正确的遍历结果。

#### 占位符清单

| # | 位置 | 当前代码 | 需要替换为 |
|---|------|----------|-----------|
| P1 | `GenerateInitBlock` L503 | `(void)init_phase;` | `SaveState(init_phase)` 保存初始 phase |
| P2 | `GenerateInitBlock` L507-510 | `(void)zero;` | 初始化 `stack_top_reg = 0`（通过 Assign） |
| P3 | `GenerateLeftBlock` L573 | `LoadConst(left_reg, TObject)` | `LoadField(current_node_reg, "left")` |
| P4 | `GenerateLeftBlock` L591 | `(void)phase_yield;` | `SaveState(phase_yield)` 或 `Assign(phase_reg, phase_yield)` |
| P5 | `GenerateLeftBlock` has_left | 缺少 `GenerateStackPush` 调用 | 入栈 `(current_node, kRight)` + `current_node = left` |
| P6 | `GenerateYieldBlock` L609 | `LoadConst(result, TObject)` | `LoadField(current_node_reg, "value")` |
| P7 | `GenerateYieldBlock` | 无 YieldValue 指令 | 添加 `YieldValue(result)` |
| P8 | `GenerateYieldBlock` L612 | `(void)phase_right;` | `SaveState(phase_right)` |
| P9 | `GenerateRightBlock` L625 | `LoadConst(right_reg, TObject)` | `LoadField(current_node_reg, "right")` |
| P10 | `GenerateRightBlock` L639 | `(void)phase_backtrack;` | `SaveState(phase_backtrack)` |
| P11 | `GenerateRightBlock` has_right | 缺少 `GenerateStackPush` 调用 | 入栈 `(current_node, kBacktrack)` + `current_node = right` |

#### BacktrackBlock 的问题

| # | 位置 | 问题 | 需要 |
|---|------|------|------|
| B1 | L670 | `(void)node_reg;` | `Assign(current_node_reg, node_reg)` |
| B2 | L671 | `(void)phase_reg;` | 从 `GenDataFooter.popped_phase` 读取 phase（需新增 HIR 指令或使用 LoadState 变体） |

## 四、Task 5：状态机逻辑实现

**目标**: 替换所有占位符，使状态机产生正确的遍历结果。

### 5.1 字段访问实现

**问题**: `LoadField` 指令需要知道字段在对象中的偏移量。CinderX 的 `LoadField` 使用名称索引。

**实现方案**:
```cpp
// GenerateLeftBlock: 加载 current_node->left
Register* left_reg = ctx_.func->env.AllocateRegister();
bb->append<LoadField>(left_reg, ctx_.current_node_reg, "left");

// GenerateYieldBlock: 加载 current_node->value
Register* value_reg = ctx_.func->env.AllocateRegister();
bb->append<LoadField>(value_reg, ctx_.current_node_reg, "value");

// GenerateRightBlock: 加载 current_node->right
Register* right_reg = ctx_.func->env.AllocateRegister();
bb->append<LoadField>(right_reg, ctx_.current_node_reg, "right");
```

**注意**: 需要确认 `LoadField` 的确切签名。参考 `hir.h` 中 `LoadField` 的定义和 `isTreeIterPattern` 中已有的 `LoadField` 使用方式。

### 5.2 Phase 状态管理

**问题**: 当前 phase 变更被 `(void)` 丢弃，状态机无法跟踪执行阶段。

**实现方案**: 使用 `Assign` 指令更新 `ctx_.phase_reg`：
```cpp
// 更新 phase_reg
bb->append<Assign>(ctx_.phase_reg, phase_yield);
```

### 5.3 YieldValue 集成

**问题**: `GenerateYieldBlock` 中没有 `YieldValue` 指令，状态机无法向调用者返回值。

**实现方案**: 参考 `YieldValue` 的使用方式（需要 FrameState）：
```cpp
Register* value_reg = ctx_.func->env.AllocateRegister();
bb->append<LoadField>(value_reg, ctx_.current_node_reg, "value");
bb->append<YieldValue>(value_reg, /* frame_state */);
```

**风险**: `YieldValue` 需要 FrameState 参数，可能需要从原始 YieldFrom 中获取。如果不兼容，可考虑使用 `YieldFromInline` 的变体。

### 5.4 StackPush 集成

**问题**: `GenerateStackPush` 已实现但未被 Left/Right 块调用。

**实现方案**:
```cpp
// GenerateLeftBlock has_left 分支：
GenerateStackPush(ctx_.current_node_reg, TreeIterPhase::kRight);
ctx_.current_node_reg = left_reg;  // 需要使用 Assign
bb->append<Assign>(ctx_.current_node_reg, left_reg);

// GenerateRightBlock has_right 分支：
GenerateStackPush(ctx_.current_node_reg, TreeIterPhase::kBacktrack);
ctx_.current_node_reg = right_reg;
bb->append<Assign>(ctx_.current_node_reg, right_reg);
```

**注意**: `GenerateStackPush` 当前硬编码写入 `bb_left_`，需要改为接受 `BasicBlock*` 参数。

### 5.5 StackPop 返回值使用

**问题**: Pop 返回的 `node_reg` 和 `phase_reg` 被 `(void)` 丢弃。

**实现方案**:
```cpp
auto [node_reg, phase_reg] = GenerateStackPop();
stack_not_empty->append<Assign>(ctx_.current_node_reg, node_reg);
stack_not_empty->append<Assign>(ctx_.phase_reg, phase_reg);
```

**Phase 读取**: 当前 `GenerateStackPop` 中 phase 使用零值占位符。需要添加 `LoadPoppedPhase` HIR 指令来读取 `GenDataFooter.popped_phase`，或修改 `StateStackPop` 的 codegen 将 phase 写入第二个 LIR 输出。

### 5.6 stack_top 初始化

**问题**: `GenerateInitBlock` 中 `stack_top_reg` 未初始化。

**实现方案**: 使用 `Assign` 指令：
```cpp
Register* zero = CreateIntConst(bb, 0);
bb->append<Assign>(ctx_.stack_top_reg, zero);
```

### 5.7 BacktrackBlock 栈空检查

**问题**: 使用未初始化的 `stack_top_reg` 进行比较。

**实现方案**: 在 `stack_top_reg` 初始化后（5.6），此检查应自动正确工作。

**依赖**: Task 5

### 6.1 深度超限回退

**当前状态**: `generateStateMachine` 中已有 `yield_froms.size() > kMaxInlineDepth` 检查。

**补充**: 需要验证回退路径是否正确（YieldFrom 不被删除，保持原有行为）。

### 6.2 空树和单节点树

**测试用例**:
```python
def test_empty_tree(self):
    tree = None
    result = list(iter(tree)) if tree else []
    self.assertEqual(result, [])

def test_single_node(self):
    tree = Node(1)
    result = list(tree)
    self.assertEqual(result, [1])

def test_left_only_tree(self):
    tree = Node(3, Node(2, Node(1)), None)
    result = list(tree)
    self.assertEqual(result, [1, 2, 3])

def test_right_only_tree(self):
    tree = Node(1, None, Node(2, None, Node(3)))
    result = list(tree)
    self.assertEqual(result, [1, 2, 3])
```

## 八、风险和缓解

| 风险 | 影响 | 概率 | 缓解策略 |
|------|------|------|----------|
| LoadField 无法在生成器内联上下文中使用 | 高 | 中 | 研究 `isTreeIterPattern` 中已有的 LoadField 使用方式，必要时使用 LoadAttr 替代 |
| YieldValue 需要 FrameState | 高 | 中 | 从原始 YieldFrom/Yield 指令中提取 FrameState，或使用 YieldFromInline 变体 |
| Assign 指令不存在 | 中 | 低 | 检查 HIR 中是否有等效指令（如 Move/Copy），或直接在 LoadConst 中覆盖目标寄存器 |
| Phase 通过 popped_phase 读取效率低 | 低 | 低 | 修改 StateStackPop codegen 使用两个输出寄存器（需要扩展 LIR 多输出支持） |
| 寄存器分配冲突 | 中 | 中 | 在 Generate() 中一次性分配所有寄存器，确保生命周期正确 |
